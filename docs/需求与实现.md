# 需求与实现说明

## 一、原始需求

**第一轮**

> 对这个街景进行 3D 实景建模，做成 html，方便我引用使用。

输入是一张城市街区十字路口的航拍俯视图（照片以对话内联图片形式提供，
未落盘为文件，因此本仓库不含该原图；场景要素依据照片判读重建）。

拆解出的隐含要求：单文件、可离线、可嵌入引用、移动端可用。

**第二轮（v2.0 的五项功能）**

1. 进行建模分层，每个建筑和车都有自己的 ID 和 name，点击时弹框显示。
2. 地图长按标记起点、途经、终点，并链接成线。
3. 做一个假人，我可以控制他的移动。
4. 增加 2/3D 切换按钮，2D 看整体布局。
5. 2D 和 3D 都能旋转、拖拽。

## 三、技术方案

### 3.1 单文件离线

Three.js r160 与 OrbitControls 通过 esbuild 打进一个 `<script type="module">`，
运行时零 CDN、零网络请求（`test/offline.js` 断言）。

装配流程见 `scripts/build.sh`。关键坑：把 bundle 注入 `shell.html` 的占位符时
**必须**用 `split('__APP_JS__').join(js)`，若用 `String.replace`，压缩后的 three.js
里出现的 `$&` 等模式会被展开成 shell 全文，产物直接损坏。

### 3.2 程序化贴图

所有贴图由 Canvas 2D 现画，无外部图片：立面（混凝土 / 车库 / 玻璃 / 工业 / 深色 / 白墙）、
屋顶（灰 / 白 / 绿 / 深 / 沥青 / 停车楼，含破损洞）、地面总图（道路、人行道、车道虚线、
停车位）、红瓦、渐变天空（随日照角度重绘）。

### 3.3 几何批处理与可拾取性的权衡

`part(geo, x, y, z, col, rx, ry, rz)` 生成带变换的非索引几何并写入顶点色，
`mergeGeo` / `mergeParts` 合并为单个 Mesh。女儿墙、空调机组、废墟、树木、电线杆、
远景天际线等重复要素走批处理（远景用 `MeshBasicMaterial` 免光照），
draw calls 从约 800 降到 60–190。

建筑与车辆**不合并**，各自保留独立 Mesh 以便点选；机库这类非盒体形状用
`pickBox()` 生成一个不可见（`colorWrite:false`）但可射线命中的代理盒。

### 3.4 建模分层（需求 1）

`REG` 注册表 + 四个图层 Group：`建筑层 / 车辆层 / 人物层 / 标注层`。
`reg(obj, info, group)` 写入 `userData.info`（ID、name、类型、层数、尺寸、坐标、状态）
并归入图层，面板可整层显隐。

ID 规则：`BLD-nn`（建筑 / 机库）、`VEH-nn`（车辆）、`PER-01`（假人）、`RTE-nn`（路线点）。

### 3.5 点选弹框（需求 1）

`Raycaster.intersectObjects(REG, true)`，向上回溯到带 `userData.info` 的注册对象；
`onScreen()` 沿父链检查可见性，被隐藏的图层不会被选中。

为区分「点选」与「拖拽旋转」：按下位移 > 11 px 或按住 > 480 ms 即判定为手势，
不触发选中。选中后画一个橙色 `EdgesGeometry` 描边框，每帧 `syncSel()` 跟随对象
（行驶车辆、假人）更新位置，并把实时坐标写回弹框单元格。

### 3.6 长按路线标记（需求 2）

`pointerdown` 起 520 ms 定时器，期间无显著位移才生效；命中点优先取实体表面
（长按屋顶时标记落在屋面高度），否则取 `y=0` 地面平面，并限制在地图 97 m 半径内。
触发时临时 `controls.enabled = false`，避免与 OrbitControls 抢手势，移动端调用
`navigator.vibrate` 给触觉反馈。

标记为「地面圆环 + 立杆 + 圆锥 + 编号球 + 屏幕端 Sprite 编号气泡」。角色随点数动态
判定：第 1 个是起点（绿）、最后 1 个是终点（红）、中间都是途经（琥珀），撤销后
前面点的角色会自动回退重算。连线用 `LineDashedMaterial` + `computeLineDistances()`，
总长按平面距离累加显示。

### 3.7 可控假人（需求 3）

由 `limb()` 搭出分段人形（头 / 躯干 / 双臂 / 双腿 / 鞋 + 头发 + 脚下定位环），
`_skel` 记录带相位的手臂与髋部枢轴，按行进速度驱动正弦摆动。

输入合并：虚拟摇杆向量 + WASD / 方向键，Shift 奔跑。方向为**屏幕相对**——用
`activeCam.matrixWorld` 的列向量投影到 XZ 平面，把「屏幕上」映射成世界前向，
因此任意视角下操作直觉一致；朝向以 12 rad/s 平滑转向。

碰撞用 AABB：遍历 `userData.solid` 的注册对象，X、Z 两轴分别尝试推进，
实现贴墙滑行；位置限制在 ±97 m。跟随视角以插值把 `controls.target` 与相机
拉到假人身后 11 m、高 7.5 m 处。

虚拟摇杆用 Pointer Events + `setPointerCapture`（合成事件下可能抛
`NotFoundError`，已 try/catch 兜底），摇杆自身 `stopPropagation`，
不与地图长按冲突。

### 3.8 2D/3D 切换与双模式操作（需求 4、5）

3D 沿用 OrthographicCamera + OrbitControls（`up = (0,1,0)`，
`maxPolarAngle = 89.1°` 防止翻到地底），街景视角切 PerspectiveCamera 沿
`driveCurve` 行车。

2D 是正交相机垂直俯视（`y = 205`）。这里没有复用 OrbitControls：其
`maxPolarAngle` 与 `up` 向量在正上方附近会退化，旋转手感不可控。改为自写的
轻量控制器，状态只有 `psi`（绕 Y 的方位角）、`zoom`、`tx/tz`（视点中心）：

- 单指 / 单键拖拽 → 沿当前 `up` 基底平移，屏幕像素到世界米的换算与 zoom 一致
- 双指距离变化 → 缩放，双指夹角变化 → 旋转，一次手势同时完成
- 滚轮 → 缩放；`⟲ 左转 / 右转 ⟳` → 每次 15°
- `up` 取 `(−sinψ, 0, −cosψ)`，保证旋转后地图文字与标记仍正对观察者

视锥半高由 `m2half()` 按屏幕长宽比反算，保证 216 m 见方的完整街区入画，
竖屏（412×860）也能看到整体布局。切回 3D 时恢复 `up=(0,1,0)`、`zoom=1` 并飞回斜视航拍。

点选与长按在两种模式下共用同一套代码，`activeCam` 决定射线来源。

## 四、验证

无头环境跑 WebGL 需要软件渲染：puppeteer-core + chromium，在
`xvfb-run -a` 下配 `LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe`
（直接跑会 `EGL_NOT_INITIALIZED`）。页面暴露 `__SCENE_READY__ / __scene / __cam /
__pcam / __REG / __pickAt / __dummyStep / __stickV` 供脚本断言。

因软件渲染仅约 1.5–25 FPS，逐帧积分的假人在真实帧下位移很小，故用
`__dummyStep(n)` 以固定 1/60 s 步长离线推进来验证运动学与碰撞：
前进 2 s ≈ 3.2 m（与 1.55 m/s 一致），撞楼停在墙面外沿，跑动 2 s ≈ 8.4 m。

v2.0 回归结论：各场景 0 页面报错、0 外部请求，约 17k 三角面 / 60–190 draw calls；
2D 双指捏合缩放 1 → 3.54、旋转后 `up` 由 `(0,0,−1)` 变为 `(0.64,0,−0.77)`；
路线 3 点 74 m、撤销回 2 点 37 m、清除归零。

## 五、已知边界

- 参考原图为对话内联图片，未保存为文件，仓库内不含原图。
- 2D 模式下建筑高度信息仅通过描边与阴影体现，未做立面简化（正射）渲染。
- 假人碰撞为轴对齐盒近似，斜向机库等异形体使用代理盒。
- `LineDashedMaterial.linewidth` 受 WebGL 限制，移动端虚线粗细固定为 1 px。
